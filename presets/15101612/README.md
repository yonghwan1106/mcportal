## 3. 큐레이션이 바꾼 것 / 바꾸지 않은 것

**바꾼 것**

- **서비스 설명을 4문장으로 압축.** 원 `info.description` 은 무역통계 개론이라
  도구 설명으로는 장황하다. 압축본은 집계 기준(수출 최종목적국 / 수입 원산국,
  수출 FOB · 수입 CIF 미화 달러)과 갱신 주기(매월 15일경)만 남겼다. **원문은
  `source.json` 의 `document.info.description` 에 그대로 있다.**
- 오퍼레이션 요약·설명. 짝 데이터셋을 가리키는 문장을 넣어 두 도구가 함께 노출될 때
  LLM 이 고를 수 있게 했다(양쪽 번들 모두에 상호 참조를 넣었다).
- 예시 프롬프트 3개(단일 국가 / 기간 범위 / 무역수지 비교).
- 파라미터 힌트 3종. 국가 코드에는 대표값과 정본 출처를 알려 주는 안내 문장
  (`enum_note`)을 붙였다.
- 응답 스키마를 **미확정으로 강등**(근거는 §4).

**바꾸지 않은 것**

- 파라미터의 타입·필수 여부, 경로, 메서드, base_url.
- 필수 파라미터의 예시값 — **어댑터가 채운다**(§5).

## 4. 응답 스키마를 미확정으로 강등한 이유

원 스펙의 200 응답 스키마는 두 군데가 실제 XML 과 어긋난다.

1. 최상위에 `header`/`body` 를 두고 루트 래퍼 이름을 형제 키로 붙였다. 실제 XML 은
   래퍼 엘리먼트가 한 겹 더 있으므로 **XML→JSON 정규화 결과는 한 단계 더 깊다.**
2. 반복되는 항목 엘리먼트가 단일 객체로 선언돼 있으나 실제로는 여러 개 반복된다 →
   정규화 결과는 **배열**이다.

틀린 스키마를 도구에 노출하느니 미확정으로 두고 추론에 맡기는 편이 안전하다.
`curation.json` 의 `response.unresolved` 에 근거와 함께 적었고, 산출물의
`info.x-mcportal.schema_inference.unresolved` 가 `1` 로 나온다.

## 5. 국가 코드를 열거값으로 전개하지 않은 이유

참고문서 `관세청조회코드_v1.2.xlsx` 의 '국가코드' 시트가 정본이다. 200개가 넘는
코드를 `schema.enum` 에 실으면

- 도구 스키마가 비대해져 LLM 프롬프트 토큰을 낭비하고,
- 코드가 개정되면 스펙이 조용히 상한다.

그래서 **열거값으로 전개하지 않고** 설명 말미의 안내 문장(`enum_note`)으로 대표값
5개와 정본 출처만 알려 준다. 안내 문장은 파라미터 설명에 합쳐지고
`schema.enum` 에는 실리지 않는다.

## 6. 실데이터의 지저분함(기록)

- `host` 에 경로가 들어 있고 `basePath` 가 빈 문자열이다(Swagger 2.0 위반).
  MCPortal 은 `스킴 + host + basePath` 를 이어 붙이므로 우연히 올바른 base_url 이
  나온다. 표준 검증기를 파이프라인에 붙이더라도 **입력 문서가 아니라 산출 문서에만**
  적용해야 한다.
- 표준 `parameters` 에 `example`·`default` 가 **하나도 없다.** 실제 예시값은 포털
  게이트웨이가 표준 Swagger 옆에 함께 싣는 **비표준 메타 블록**에만 있다. 예시값이
  없으면 샘플러가 필수 파라미터 값을 만들 수 없어 응답 스키마 추론이 시작조차
  못 하므로, 어댑터가 이 블록을 **포털 공통 포맷으로서** 흡수해 빈 `example` 만
  채운다(매칭이 모호하면 아무것도 적용하지 않는다).
- `definitions` 가 `paths` 에서 한 번도 참조되지 않는다(전부 인라인). 무해하므로
  원문 그대로 둔다.
- 스칼라 리프마다 빈 `"properties": {}` 가 덧붙어 있다. 산출 문서로 새어 나가지
  않도록 정규화 단계에서 제거한다.
