# MCPortal 프리셋 — 3종(4데이터셋)

공공데이터포털(data.go.kr)의 실제 공개 스펙으로 만든 프리셋 번들이다. MCPortal 의
**2층 구조**(아래층 = 기계적 자동변환 / 위층 = 사람이 확인한 큐레이션)를 코드가
아니라 **데이터로** 보여 주는 것이 이 디렉터리의 목적이다.

| ID | 서비스 | 도메인 | 소스 종류 | 오퍼레이션 | 응답 미확정 | 이용허락범위 |
|---|---|---|---|---|---|---|
| `15000115` | 법제처 국가법령정보 공유서비스 | 법령 | `rest_doc_manual` | 8 | 8 | 공공누리 제1유형(출처표시) |
| `15081808` | 국세청 사업자등록정보 진위확인·상태조회 | 사업자등록 | `odcloud_swagger` | 2 | 0 | 제한 없음 |
| `15101612` | 관세청 국가별 수출입실적 | 관세 | `gw_swagger` | 1 | 1 | 제한 없음 |
| `15102108` | 관세청 수출입총괄 | 관세 | `gw_swagger` | 1 | 1 | 제한 없음 |

도메인 기준으로는 **3종**(법령 / 사업자등록 / 관세)이고, 관세만 데이터셋이 2개다.
그래서 모든 문서에서 **"3종(4데이터셋)"**으로 표기한다. 묶음 라벨은 각
`curation.json` 의 `service.group` 에 있다.

---

## 1. 번들 레이아웃

```
presets/
├─ README.md                  ← 이 문서(규약·2층 구조·미해결 항목)
├─ NOTICE-DATA.md             ← 스펙 메타데이터·참고문서 출처 정본
├─ _MANIFEST_20260806.json    ← 정찰 산출물(경로·bytes·sha256·출처 URL·취득일)
├─ _raw/…                     ← 정찰이 받은 원문(수정 금지)
├─ _transcribed/…             ← 사람이 전사한 기술서(수정 금지)
└─ <preset_id>/
    ├─ source.json            ← 스펙 원문 + 출처·취득일·지문(아래층 입력)
    ├─ curation.json          ← 사람이 확인한 설명·예시·힌트(위층 입력)
    ├─ openapi.json           ← 두 층을 병합한 산출물(커밋 대상)
    └─ README.md              ← 이 데이터셋의 출처·미해결 항목
```

이름이 `_` 로 시작하는 디렉터리는 프리셋으로 취급하지 않는다(`iter_presets` 가
제외한다).

## 2. 2층 구조 — 무엇을 바꾸고 무엇을 안 바꾸나

| 층 | 담당 | 파일 |
|---|---|---|
| 아래층(엔진) | 스펙 문서 → 중간표현 → OpenAPI 3.1. 도메인 지식 0 | `src/mcportal/compiler/**` |
| 위층(큐레이션) | 도구 설명·파라미터 힌트·예시 프롬프트·열거값 안내 | `presets/<id>/curation.json` |

**큐레이션이 바꾸는 것**: 서비스 설명, 오퍼레이션 요약·설명, 태그, 예시 프롬프트,
파라미터 설명·예시·기본값·열거값, 열거값 안내 문장.

**큐레이션이 바꾸지 않는 것**: 파라미터의 타입·위치·필수 여부·배열 원소 타입,
오퍼레이션의 경로·메서드·식별자, 요청 본문 스키마. 이 값들은 원 스펙 선언이
정본이며, 틀렸다면 큐레이션으로 덮는 것이 아니라 **스펙 소스를 재취득한다.**

사실을 교정하는 통로는 **근거를 요구하는 두 가지**뿐이다.

* `operations[*].response.unresolved` — 응답 스키마를 미확정으로 강등(`reason` 필수)
* `operations[*].parameters_remove` — 파라미터 제거(`reason` 필수, 필수 파라미터는 불가)

`curation.json` 의 `example_prompts` 는 문서가 아니라 **데이터**다. 벤치마크
하네스가 툴콜 성공률을 잴 때 이 문구를 프롬프트 원본으로 그대로 읽는다.

## 3. 재생성

```
mcportal compile            # 전 프리셋 재생성(내용이 같으면 파일을 다시 쓰지 않는다)
mcportal compile 15101612   # 지정 프리셋만
mcportal compile --check    # 파일을 쓰지 않고 바이트 비교만(드리프트가 있으면 종료 코드 3)
```

**같은 `source.json` + `curation.json` 이면 `openapi.json` 은 바이트 동일해야 한다.**
JSON 의 키 순서를 뒤집어도 결과는 같다.

⚠️ 예외 하나: `info.x-mcportal.tool_version` 이 `mcportal.__version__` 이므로
**패키지 버전을 올리면 4개 `openapi.json` 이 전부 바뀐다.** 이는 정상이며, 버전
승격 시 `mcportal compile` 로 재생성하는 것이 규약이다.

## 4. 응답 스키마 12건 중 10건이 아직 비어 있다

12개 오퍼레이션 중 **10개의 응답 스키마가 미확정**이다(`15000115` 8건,
`15101612` 1건, `15102108` 1건). 숨기지 않고 산출 문서의
`info.x-mcportal.schema_inference.unresolved` 에 숫자로 남긴다.

미확정 자리는 **v0.2 실키 샘플링에서 채워진다.** W3 는 인증키를 한 번도 쓰지
않았고 게이트웨이 데이터 호출도 0회이므로, 실제 응답 구조는 아직 확인된 바가
없다. 확인되지 않은 것을 확인된 것처럼 적지 않는 것이 이 프로젝트의 규칙이다.

## 5. 미해결 항목(v0.2 최우선 검증)

| # | 항목 | 대상 |
|---|---|---|
| 1 | 경로 접미사 `.do` 유무 — 포털 상세기능은 `.do` 있음, 활용가이드(2022-10-19)는 없음 | `15000115` |
| 2 | 응답 XML 의 루트 래퍼 한 겹과 반복 엘리먼트의 배열성(정찰 F-06) | `15101612` · `15102108` |
| 3 | 본문형 오퍼레이션이 `returnType` 을 실제로 받는지, `page`·`perPage` 를 정말 무시하는지 | `15081808` |
| 4 | 인증키의 위치(query/header)를 중간표현이 표현하지 못한다(정찰 F-08) | 전체 · W4 이월 |
| 5 | 큐레이션 근거를 산출 문서에 남길 벤더 확장 통로가 없다(정찰 F-07) | 전체 · W4 이월 |

## 6. 실데이터가 규격을 벗어나는 방식(기록)

프리셋을 만들며 확인한, 실제 포털 문서의 규격 이탈 사례다. 전부 **원문 그대로
보존**하고 흡수 쪽에서 처리했다.

* 게이트웨이 Swagger 2.0 문서의 `host` 에 경로가 들어 있고 `basePath` 가 빈
  문자열이다(Swagger 2.0 위반). 포털 관용 표기로 인정한다 — 표준 검증기를
  붙이더라도 **입력 문서가 아니라 산출 문서에만** 적용한다.
* 필수 파라미터의 예시값이 표준 `parameters` 가 아니라 비표준 메타 블록에만 있다.
* 응답 코드 목록에 비-HTTP 키(`-5`)가 섞여 있다.
* `definitions` 가 `paths` 에서 한 번도 참조되지 않고, 선행 공백이 붙은 오타 키가
  정상 키와 함께 존재한다.
* 스칼라 리프마다 빈 `"properties": {}` 가 덧붙어 있다(정규화로 제거).
* 항목명(영문) 칸에 한글이 들어와 응답 프로퍼티 이름이 한국어가 된다(JSON Schema
  상 문제 없음 — 그대로 보존).
* 같은 데이터셋에 스펙 문서가 두 벌 있고, 흔히 쓰이는 쪽이 메서드부터 다른
  껍데기다.

## 7. 안전 규칙

* **실인증키 0.** 프리셋을 만드는 동안 인증키를 한 번도 쓰지 않았고 게이트웨이
  데이터 호출도 0회다. 스펙 메타데이터만 무인증으로 받았다.
* `source.json` 의 `document` 는 **원문 그대로**다. 정부 스펙 문서의 관용 표기인
  `인증키=<자리표시자>` 형태 문자열이 그대로 남아 있을 수 있다(자리표시자는
  `[서비스키]` · `xxxxxx` 뿐이며 실제 값은 없다). 그 문자열이 산출물로 흘러
  들어가는 경로는 `curation.json` 의 `service.description` 교체로 끊는다.
* 산출물(`openapi.json`)에는 인증키 대입이 **0건**이고 인증키 파라미터도 없다
  (인증키는 트랜스포트가 주입한다).
* 개인정보 0. 스펙에 실린 예시값은 전부 자리표시자다. 출처와 근거는
  [`NOTICE-DATA.md`](NOTICE-DATA.md) 를 정본으로 한다.
