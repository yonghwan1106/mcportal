## 3. 큐레이션이 바꾼 것 / 바꾸지 않은 것

**바꾼 것**

- 서비스 설명을 "여덟 갈래를 각각 별도 도구로 제공한다"는 **도구 선택 안내**로 교체.
- 8개 오퍼레이션의 요약·설명을 **서로 구분되게** 다시 씀. 자동생성만으로는 8개가
  전부 "…목록 조회"라 LLM 이 고를 수 없다(이 프리셋의 큐레이션 핵심 효용).
- 오퍼레이션마다 예시 프롬프트 2개(총 16개). 벤치마크의 "도구 선택 정확도" 표본.
- 파라미터 힌트 4종(`target`·`query`·`numOfRows`·`pageNo`).
- `query` 의 예시값을 `*` 로 교정. → §4 참조.

**바꾸지 않은 것**

- 파라미터의 타입·위치·필수 여부, 경로, 메서드, 열거값·기본값(`target` 의 고정값은
  원 표 그대로).
- 응답 스키마(원래부터 미확정 — 강등 지시를 쓰지 않았다).

## 4. 실키 샘플링으로 확정한 것 (v0.2.0, 2026-08-09)

응답 스키마 8건을 **오퍼레이션당 1회씩 총 8회 실호출**로 확정했다. 추론 결과는
`sampled_schemas.json` 에 영속화되어 있고(`conflicts` 0 · `truncated` false),
응답 본문은 `samples/` 에, 요청·응답 쌍은 `cassettes/15000115.json` 에 남아 있어
**인증키 없이 재현**된다. 산출물의 `info.x-mcportal.generation_mode` 가
`sampled`, `sample_count` 가 `8` 로 나온다.

확정된 응답 루트 엘리먼트는 오퍼레이션마다 다르다 — `lawSearchList`→`LawSearch`,
`admrulSearchList`→`AdmRulSearch`, `ordinSearchList`→`OrdinSearch`,
`expcSearchList`→`Expc`, `detcSearchList`→`DetcSearch`,
`licbylSearchList`→`licBylSearch`, `lstrmSearchList`→`LsTrmSearch`,
`trtySearchList`→`TrtySearch`. 이름 규칙이 일정하지 않고(`Expc` 만 `Search` 접미가
없고 `licBylSearch` 만 소문자로 시작한다) 스펙 문서에는 이 이름이 적혀 있지 않다.
추론 없이는 알 수 없는 값이었다는 뜻이다.

**경로 접미사 `.do` 는 맞았다.** 포털 상세기능은 `/lawSearchList.do`, 활용가이드
(2022-10-19)는 `/lawSearchList` 로 적었고 더 최근인 포털 표기(수정일 2025-07-04)를
채택했는데, 2026-08-09 실호출에서 **8개 오퍼레이션 전부 `.do` 경로로 정상
응답**했다(`resultCode` 정상). 무접미 경로와의 대조 호출은 하지 않았으므로 "무접미는
동작하지 않는다"는 주장은 하지 않는다.

⚠️ **샘플 데이터의 이용조건.** `samples/` 의 응답 본문은 공공누리 **제1유형
(출처표시)** 인 법제처 국가법령정보 데이터 조각이다. 재배포·재사용 시 출처
표시가 필요하다 — 문구는 [`../NOTICE-DATA.md`](../NOTICE-DATA.md) 를 따른다.

## 5. 미해결 항목

1. **`query` 예시값 `10` → `*` 교정.** 포털 상세기능 표에서 8개 중
   `lawSearchList`(oprtinSeqNo=20283) 하나만 샘플이 `10` 이고 나머지 7개는 `*`
   이며, 같은 행의 기본값도 `*` 다. 포털 표 자체의 오타로 판단해 큐레이션에서
   `*` 로 교정했다. **원 표기는 `source.json` 의
   `document.operations[].parameters[].example` 에 `"10"` 으로 그대로 있다.**
2. **`query` 의 검색 문법 — 여전히 미확정.** 낱말을 여러 개 넣었을 때의 결합
   규칙(AND/OR), 구문 검색·와일드카드 지원 여부가 전부 미확인이다. 상세기능
   표·활용가이드 어디에도 문법 설명이 없어, 초안이 적었던 "여러 낱말을 모두 포함"
   서술은 근거가 없어 삭제했다(2026-08-09 Advisor 검증 V3). **2026-08-09 샘플링은
   전 오퍼레이션을 `query=*` 단일 값으로만 호출했으므로 이 항목을 판정하지
   못했다.** 낱말 2개 이상을 넣은 호출 2~3건이면 판정된다.

## 6. 실데이터의 지저분함(기록)

- 출력결과 표의 "항목명(영문)" 칸에 한글이 들어오는 행이 있다(실제 XML
  엘리먼트명이 `법령일련번호`·`현행연혁코드` 처럼 한글). JSON Schema 상 문제가
  없으므로 그대로 보존한다. `operation_id` 정규화 규칙과 혼동하지 말 것.
- 포털 첨부 활용가이드(docx)는 담당 공무원 실명·직통전화·이메일을 담고 있어
  **리포에 보존하지 않았다.** 사유는 `_raw/15000115/NOTE_참고문서_미보존.md`.
- 실응답의 `법령상세링크` 값에 **상류 서비스가 자기 쪽 계정 식별자를 박아
  보낸다**(`/DRF/lawService.do?OC=<식별자>&...`). MCPortal 은 이 파라미터를 보낸
  적이 없다 — 법제처가 응답에 넣어 주는 값이며, `samples/` 8개 파일에 그대로 남아
  있다. 자연인의 개인정보로 보이지는 않으나 상류 계정 식별자이므로 기록해 둔다.
