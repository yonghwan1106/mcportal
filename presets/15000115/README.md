## 3. 큐레이션이 바꾼 것 / 바꾸지 않은 것

**바꾼 것**

- 서비스 설명을 "여덟 갈래를 각각 별도 도구로 제공한다"는 **도구 선택 안내**로 교체.
- 8개 오퍼레이션의 요약·설명을 **서로 구분되게** 다시 씀. 자동생성만으로는 8개가
  전부 "…목록 조회"라 LLM 이 고를 수 없다(이 프리셋의 큐레이션 핵심 효용).
- 오퍼레이션마다 예시 프롬프트 2개(총 16개). 벤치마크의 "도구 선택 정확도" 표본.
- 파라미터 힌트 4종(`target`·`query`·`numOfRows`·`pageNo`).
- `query` 의 예시값을 `*` 로 교정. → §4 참조.

**바꾸지 않은 것**

- 파라미터의 타입·위치·필수 여부, 경로, 메서드, 열거값·기본값(`target` 의 고정값은
  원 표 그대로).
- 응답 스키마(원래부터 미확정 — 강등 지시를 쓰지 않았다).

## 4. 미해결 항목 (v0.2 최우선 검증)

1. **경로 접미사 `.do` 유무.** 포털 상세기능은 `/lawSearchList.do`, 활용가이드
   (2022-10-19)는 `/lawSearchList` 로 적었다. 더 최근인 포털 표기(수정일
   2025-07-04)를 채택했다. 틀렸다면 `source.json` 의 `document` 를 손으로 고치는
   것이 아니라 **재취득**한다.
2. **`query` 예시값 `10` → `*` 교정.** 포털 상세기능 표에서 8개 중
   `lawSearchList`(oprtinSeqNo=20283) 하나만 샘플이 `10` 이고 나머지 7개는 `*`
   이며, 같은 행의 기본값도 `*` 다. 포털 표 자체의 오타로 판단해 큐레이션에서
   `*` 로 교정했다. **원 표기는 `source.json` 의
   `document.operations[].parameters[].example` 에 `"10"` 으로 그대로 있다.**
3. **응답 XML 의 중첩 구조.** 출력결과 표가 평면 목록이라 XML 중첩을 담지 못한다.
   그래서 8건 전부 `response_schema` 를 비워 두었다(추론 대상).
4. **인증키 위치.** 인증키는 질의 파라미터로 전달하지만, 중간표현은 키의
   위치(query/header)를 표현하지 않는다(정찰 F-08, W4 이월).
5. **`query` 의 검색 문법.** 낱말을 여러 개 넣었을 때의 결합 규칙(AND/OR),
   구문 검색·와일드카드 지원 여부가 전부 미확인이다. 상세기능 표·활용가이드
   어디에도 문법 설명이 없어, 초안이 적었던 "여러 낱말을 모두 포함" 서술은
   근거가 없어 삭제했다(2026-08-09 Advisor 검증 V3). 실키 호출 2~3건이면
   판정된다.

## 5. 실데이터의 지저분함(기록)

- 출력결과 표의 "항목명(영문)" 칸에 한글이 들어오는 행이 있다(실제 XML
  엘리먼트명이 `법령일련번호`·`현행연혁코드` 처럼 한글). JSON Schema 상 문제가
  없으므로 그대로 보존한다. `operation_id` 정규화 규칙과 혼동하지 말 것.
- 포털 첨부 활용가이드(docx)는 담당 공무원 실명·직통전화·이메일을 담고 있어
  **리포에 보존하지 않았다.** 사유는 `_raw/15000115/NOTE_참고문서_미보존.md`.
