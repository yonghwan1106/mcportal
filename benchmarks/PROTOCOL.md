# MCPortal 벤치마크 프로토콜 (선등록)

> 판본: 1 · 최종 개정: 2026-08-06 · 작성 시점: **측정 실행 이전**
> 대상 리포: `mcportal` (Apache-2.0) · 하네스: `benchmarks/harness.py` · 결과: `benchmarks/results/`

이 문서는 **측정을 실행하기 전에 확정된 계획서**다. 무엇을 · 어떻게 · 몇 번 재고,
어떤 통계로 요약하며, 어떤 결론이 나오면 그것을 어떻게 읽을지를 **결과를 보기 전에**
못 박아 둔다. 그래서 이 문서에는 **측정된 수치가 한 줄도 없다.** 수치는 전부
`benchmarks/results/*.json`에만 있다.

---

## 1. 목적과 양방향 가설

### 1-1. 목적

MCPortal은 공공 오픈API 스펙을 OpenAPI 3.1로 정규화하고, 그 위에 인증키 격리 ·
쿼터 하드 가드 · 스크러빙 record/replay를 얹는 런타임 계층이다. 계층을 얹으면
비용이 생긴다. 이 벤치마크의 목적은 **그 비용을 스스로 계량해 공개하는 것**이다.

측정 대상은 MCPortal 자기 자신의 계층 비용이며, **경쟁 라이브러리와의 우열을
가리는 벤치마크가 아니다**(§8-1).

### 1-2. 양방향 가설 — 결론이 어느 쪽으로 나와도 읽는 법을 미리 정한다

큐레이션 2층 구조(자동생성 아래층 + 사람이 확인한 위층)에 대해 W3는 **무키
항목만** 실행하고, 큐레이션의 효용 자체는 실키 단계(K2, §6)에서 판정된다.
그 판정이 어느 쪽으로 나와도 서사가 성립하도록 두 결론의 해석을 여기 미리 적는다.

| 가설 | 성립했을 때의 해석 | 그때 MCPortal이 해야 할 일 |
|---|---|---|
| **H1. 큐레이션이 이긴다**(큐레이션 서버의 툴콜 성공률이 자동생성 단독보다 높다) | 자동변환만으로는 LLM이 도구를 고르고 인자를 채우기에 정보가 모자란다. "6.6만종 자동변환"은 **도달 범위**의 주장이고, 실제 사용성은 위층이 만든다 | 2층 구조를 정식 기능으로 유지하고, 큐레이션 작성 비용을 낮추는 도구(템플릿·검증기)를 다음 마일스톤에 넣는다 |
| **H2. 큐레이션이 지거나 차이가 없다** | 자동생성만으로 충분한 **조건**이 존재한다는 뜻이다. 그 조건(오퍼레이션 수가 적다 · 도메인이 겹치지 않는다 · 파라미터명이 자기설명적이다)을 규명하는 것이 결과다 | 큐레이션을 "전부에 필요한 층"이 아니라 **"필요한 곳에만 얹는 층"**으로 재포지셔닝하고, 어떤 프리셋이 그에 해당하는지 판정 기준을 문서화한다 |

**H2를 실패로 취급하지 않는다.** "어떤 조건에서 위층이 필요 없는가"는 그 자체로
공개 가치가 있는 결과이며, 이 조항을 실행 전에 적어 두는 이유는 결과를 본 뒤
서사를 고르는 것을 막기 위해서다.

무키 항목(§2)에는 승패 가설이 없다. 이 항목들은 **가설 검정이 아니라 계량**이다.
"얼마나 느린가"를 재서 공개하는 것이 목적이고, 값이 크게 나오면 그 값을 그대로
싣는다(§7-2).

## 2. 측정 항목 — 무키 5종 (W3에서 실행)

전 항목 공통: **네트워크 호출 0건 · 인증키 0건 · 실응답데이터 0건.** 상위
트랜스포트는 `httpx.MockTransport` 또는 `mcportal.replay.ReplayTransport`뿐이며,
하네스는 `httpx.HTTPTransport` · `httpx.AsyncHTTPTransport`를 **생성하지 않는다.**
모든 도메인은 RFC 2606 예약 TLD `.invalid`를 쓴다.

### B1 — replay 왕복 지연

| 항목 | 내용 |
|---|---|
| 측정 대상 | 합성 카세트를 `ReplayTransport`로 재생할 때 `httpx.Client.get()` 1회 왕복 시간 |
| 입력 | 상호작용 10건짜리 합성 카세트. 요청은 질의 파라미터 `n=0..9`로 구분되며, 측정 루프는 이를 순환한다 |
| 조건 | `payload_1kb` · `payload_64kb` (응답 본문의 목표 크기) |
| 반복 | warmup 20 · N=200 |
| 읽는 법 | 카세트 매칭은 선형 탐색이다. 상호작용 수가 늘면 이 값이 선형으로 늘어난다는 사실을 함께 읽는다(§8-2) |

### B2 — 스크러빙 오버헤드

| 항목 | 내용 |
|---|---|
| 측정 대상 | `mcportal.replay.scrub`의 `scrub_url` · `scrub_params` · `scrub_text` 각 1회 호출 시간 |
| 조건 축 | 함수 3종 x 입력 크기 2종(`1kb`·`64kb`) x 시크릿 수 2종(`s0`·`s3`) = 12조건 |
| 조건명 | `url_1kb_s0` · `url_1kb_s3` · `url_64kb_s0` · `url_64kb_s3` · `params_…` · `text_…` |
| 시크릿 수의 정의 | `url`·`params`는 **입력에 들어 있는 인증키 대입 개수**(0 또는 3). `text`는 **`secrets` 인자의 길이**(0 또는 3) |
| 합성 시크릿 | 리포 테스트 규약과 같은 합성 문자열 3종을 쓴다. 실인증키는 어떤 조건에도 등장하지 않는다 |
| 반복 | warmup 50 · N=500 |
| 읽는 법 | 스크러빙은 **끌 수 없는 게이트**다. 따라서 이 값은 "선택 기능의 비용"이 아니라 **record 경로의 고정 비용**으로 읽는다 |

### B3 — 컴파일 시간 + 결정론

| 항목 | 내용 |
|---|---|
| 측정 대상 | `load_source` → `build_openapi` → `dumps` 전 구간과 단계별 |
| 소스 | 합성 3종(`syn_gw`: 게이트웨이 Swagger 2.0형 · `syn_odcloud`: odcloud OAS 3.x형 · `syn_restdoc`: 수동 매핑 기술서형 8오퍼레이션) + **프리셋 번들(존재할 때)** |
| 조건명 | `<소스>:load` · `<소스>:build` · `<소스>:dumps` · `<소스>:total`. 프리셋은 `preset_<데이터셋ID>:<단계>` |
| 반복 | warmup 3 · N=30 |
| 결정론 | **시간이 아니라 불리언이다.** 같은 입력으로 5회 컴파일해 `dumps` 결과가 전부 바이트 동일하면 `deterministic: true`. 하나라도 다르면 `false` + **첫 불일치 문자 오프셋**을 기록한다 |
| 프리셋 부재 시 | `presets` 라는 이름의 조건 1개를 `status: "skipped"` + `reason`으로 남기고, 합성 3종만 측정한다. 항목 전체는 `ok`다 |

### B4 — 쿼터가드 오버헤드

| 항목 | 내용 |
|---|---|
| 측정 대상 | `MCPortalTransport`(가드 배선, `inner=httpx.MockTransport`) 왕복 vs **bare `httpx.Client(transport=httpx.MockTransport)`** 왕복 |
| 조건 | `guarded` · `bare` |
| 파생값 | `overhead_median_pct` · `overhead_median_ns`(중앙값 기준) **및** `overhead_mean_pct` · `overhead_mean_ns`(평균 기준). 상대 비교의 정본은 **중앙값**이다 |
| 반복 | warmup 20 · N=200 |
| 원장 | **SQLite 쓰기를 포함한 수치다.** 그것이 실제 비용이기 때문이다. 원장은 임시 디렉터리에 만들고 항목 종료 시 반드시 닫는다(Windows 파일 잠금). 저널 모드는 WAL이며 그 사실을 결과 파일 `notes`에 남긴다 |
| 예산 | 하드 예산 상한 = **(warmup + N) x 10**. 설계 §10-4의 "N x 10" 취지(측정 도중 예산이 소진되지 않게 한다)를 warmup 구간까지 포함해 적용한 값이다. 측정 중 `QuotaExhausted`가 나면 그 측정은 무의미해진다 |
| 캐시 | `cache=None`으로 끈다. TTL 캐시가 히트하면 왕복 자체를 건너뛰므로 **가드 비용이 아니라 캐시 효과**를 재게 된다 |
| 읽는 법 | 원장 쓰기가 포함된 절대값은 클 수 있다. 그 값을 그대로 싣고, 배치 쓰기 최적화 여지는 한계 절(§8-2)에 적는다 |

### B5 — FastMCP 도구 빌드 시간

| 항목 | 내용 |
|---|---|
| 측정 대상 | `mcportal.mcp.server_from_spec(document, client=...)` 1회 호출 시간(= OpenAPI 문서 → MCP 서버 객체 생성) |
| 클라이언트 | `httpx.AsyncClient(transport=httpx.MockTransport(...))`. 네트워크에 닿지 않는다 |
| 조건 | `synthetic`(합성 소스를 컴파일해 만든 OpenAPI 문서) + `preset_<데이터셋ID>`(프리셋 `openapi.json`이 있을 때) |
| 반복 | warmup 2 · N=10 |
| fastmcp 미설치 | 항목 전체를 `status: "skipped"` · `reason: "fastmcp 미설치"`로 기록하고 **전체 실행은 성공으로 끝낸다.** 하네스는 fastmcp를 설치하려 들지 않는다 |
| 프리셋 부재 시 | B3와 같은 규칙(조건 1개를 `skipped`로 남기고 합성 조건만 측정) |

## 3. 환경 기록 규칙

### 3-1. 기록하는 것

`python_version` · `implementation` · `system`(`platform.system()`) ·
`release`(`platform.release()`) · `machine`(`platform.machine()`) ·
`processor`(`platform.processor()`) · `cpu_count`(`os.cpu_count()`) ·
`sqlite_version` · `packages`(`httpx` · `mcportal` · `fastmcp`(설치돼 있을 때만)) ·
실행 라벨(`--label`) · `measured_on`(KST **날짜만**, `YYYY-MM-DD`).

### 3-2. 절대 기록하지 않는 것

`platform.node()`(호스트명) · 사용자명 · 홈 디렉터리 경로 · **절대 경로 전반**
(경로가 필요하면 리포 루트 기준 상대 경로로 바꾼다) · 환경변수 덤프 · IP ·
인증키 · 개인정보.

- 오류·건너뜀 사유 문자열도 이 규칙을 따른다. 예외 메시지에 경로가 섞일 수 있으므로,
  결과에 싣기 전에 홈 디렉터리 · 리포 루트 · 호스트명을 자리표시자로 치환한다.
- `tests/test_benchmark_harness.py`가 결과 dict 전문을 문자열화해 **금지 항목 회귀
  스캔**을 돌린다.

### 3-3. 시각 기록

- 측정 시각은 **날짜(KST)까지만** 남긴다(`measured_on`). 시·분·초는 남기지 않는다.
- 기본 결과 파일명 `bench_<YYYYMMDD>_<label>.json`의 날짜도 KST 날짜다.
- 시각은 결과 파일의 **내부 필드**이며, 컴파일 산출물(`openapi.json`)에는 어떤 시각도
  실리지 않는다(컴파일러 결정론 규약).

## 4. 반복·통계 규칙

1. 시계는 `time.perf_counter_ns()`. 벽시계(`time.time`)는 쓰지 않는다.
2. 각 조건은 **warmup을 버리고** 본 측정 N회를 남긴다.
3. 표본은 **전부 보존**한다. 결과 파일에 원자료 배열(`samples_ns`)을 그대로 싣는다.
   상한은 1,000개이며, 초과하면 균등 간격으로 표본추출해 싣고 그 사실을
   조건의 `samples_truncated: true`로 밝힌다. **통계는 언제나 전체 표본으로 계산한다**
   (실은 배열만 줄어든다).
4. 보고 통계: `n` · `min_ns` · `median_ns` · `p95_ns` · `mean_ns` · `stdev_ns`.
   - 단위는 **나노초**. `min_ns` · `median_ns` · `p95_ns`는 정수, `mean_ns` · `stdev_ns`는 실수.
   - `median_ns`: 표본 수가 짝수면 가운데 두 값의 평균을 **반올림한 정수**로 싣는다.
     반올림은 **half-up**으로 계산식을 못박는다: `floor(median + 0.5)`.
     (파이썬 내장 `round()`는 half-to-even이라 `median([1,2,3,4]) = 2.5 -> 2`가
     되어 위 문면과 어긋난다. §7 개정 이력 참조.)
   - `stdev_ns`: **표본표준편차**(`statistics.stdev`). `n < 2`면 `null`.
5. **이상치 제거·트리밍 금지.** 튀는 값은 그대로 두고 `p95`로 읽는다. 제거하면
   "유리한 수치만 골랐다"는 반박을 막을 수 없다.
6. `p95`는 **nearest-rank**로 정의한다. 오름차순 정렬 후
   **`인덱스 = ceil(0.95 x n)` (1-기반)** 번째 값이다(보간하지 않는다).
   예: `n=200`이면 `ceil(190.0)=190`번째, `n=30`이면 `ceil(28.5)=29`번째.
7. 상대 비교(B4)는 **중앙값 기준**을 정본으로 계산하고 평균 기준 값도 함께 싣는다.
   `overhead_median_pct = (guarded_median / bare_median - 1) x 100`,
   `overhead_median_ns = guarded_median - bare_median`.
8. GC: 각 **항목** 시작 전 `gc.collect()`를 1회 돌린다. 측정 구간 안에서
   `gc.disable()`은 **하지 않는다**(현실 조건을 유지한다).
9. 항목 간 순서 효과는 통제하지 않는다. 항목은 `B1 → B5` 고정 순서로 실행되며,
   그 사실을 한계(§8-2)에 적는다.

### 4-1. 기본 반복 수 표 (프로토콜 정본)

| 항목 | warmup | N |
|---|---|---|
| B1 | 20 | 200 |
| B2 | 50 | 500 |
| B3 | 3 | 30 |
| B4 | 20 | 200 |
| B5 | 2 | 10 |

- `--repeat N`은 **모든 항목의 N을 덮어쓴다.** warmup은 바뀌지 않는다. 덮어쓴
  사실은 결과 파일 `overrides.repeat`에 기록된다.
- `--quick`은 **N=5 · warmup=1** 축소 실행이며 결과 파일이 `mode: "quick"`으로
  스스로 밝힌다. **이 모드의 수치는 프로토콜 준수 실행이 아니다**(스모크·테스트 전용).

## 5. 실행 방법과 재현 절차

```
# 프로토콜 준수 실행(정본)
python benchmarks/harness.py --label <라벨>

# 스모크 실행(수치를 인용하지 말 것)
python benchmarks/harness.py --quick --label smoke

# 일부 항목만
python benchmarks/harness.py --only B2,B4
```

| 옵션 | 의미 |
|---|---|
| `--out PATH` | 결과 파일 경로. 생략하면 `benchmarks/results/bench_<YYYYMMDD>_<label>.json` |
| `--label TEXT` | 실행 라벨(기본 `dev`). **ASCII 영숫자 · `-` · `_`만 허용**(파일명 안전 · 경로 탈출 차단) |
| `--only ID[,ID…]` | 항목 부분 실행. 알 수 없는 ID는 사용법 오류(종료 코드 2) |
| `--repeat N` | 기본 N 덮어쓰기(§4-1) |
| `--quick` | 축소 실행(§4-1) |
| `--presets-root PATH` | 프리셋 루트 지정. 생략하면 리포 `presets/`를 찾고, 없으면 프리셋 조건을 건너뛴다. **명시한 경로가 디렉터리가 아니면 사용법 오류(종료 코드 2)** — 경로 오타가 "프리셋 없음"으로 조용히 흡수되지 않게 한다 |

### 5-1. 종료 코드

| 코드 | 의미 |
|---|---|
| 0 | 정상(건너뛴 항목이 있어도 정상이다) |
| 1 | 항목이 하나라도 `failed`이거나, 결과 저장이 차단됐다 |
| 2 | 사용법 오류(알 수 없는 옵션 · 부적합 라벨 · 알 수 없는 항목 ID · 디렉터리가 아닌 `--presets-root`) |

### 5-2. 재현이 보장되는 것과 보장되지 않는 것

- **보장된다**: 측정 대상 코드 경로, 입력 합성 규칙, 반복 수, 통계 정의, 결과 파일 스키마.
- **보장되지 않는다**: 시간 수치 자체. 하드웨어 · OS 스케줄러 · 백그라운드 부하에
  따라 달라진다. 그래서 결과 파일에 환경 블록(§3)을 함께 싣는다.
- 결과 파일의 `protocol` 필드에 **이 문서의 sha256 앞 12자**를 박는다. 어느 판본의
  프로토콜로 잰 수치인지 사후에 확인할 수 있다.

## 6. 실키 단계 항목 (v0.2 — 정의만 하고 W3에서는 실행하지 않는다)

아래 3항목은 **인증키가 필요하다.** W3 시점에는 선등록 정의만 존재하며,
결과 파일에도 등장하지 않는다. 정의를 지금 적어 두는 이유는, 키를 얻은 뒤에
"유리하게 나오는 판정 기준"을 고르는 일을 막기 위해서다.

### K1 — 자동변환 성공률(%)

data.go.kr API 풀 **N=30**을 대상으로 "스펙 취득 → `SourceSpec` → OpenAPI 3.1 산출
→ FastMCP 도구 생성" 4단계가 **전부** 성공한 비율. 실패는 **어느 단계에서
실패했는지로 분류해** 보고한다(부분 성공을 성공으로 세지 않는다). 표본 추출 방법과
제외 기준(폐지·링크형 등)을 실행 전에 별도 기록한다.

### K2 — 오픈웨이트 툴콜 성공률

동일 모델 · 동일 프롬프트로 **자동생성 단독** 서버와 **자동생성+큐레이션** 서버를
비교한다. 프롬프트는 각 프리셋 `curation.json`의 `example_prompts`를 **원본 그대로**
쓴다(그 필드는 문서가 아니라 데이터다). 성공 판정은 **3단계로 분리**한다.

| 단계 | 판정 |
|---|---|
| S1 도구 선택 | 의도한 오퍼레이션에 해당하는 도구를 골랐는가 |
| S2 필수 인자 충족 | 그 도구의 필수 파라미터를 빠짐없이 채웠는가 |
| S3 값 형식 적합 | 채운 값이 선언된 형식·범위에 맞는가(예: 연월 6자리) |

S1/S2/S3를 **각각** 보고한다. 합산 점수 하나로 뭉치면 어디서 이겼는지 알 수 없다.
모델·온도·시드·프롬프트 템플릿을 실행 전에 고정해 기록한다.

### K3 — 응답 스키마 추론 정확도

실키 샘플 **3~5건**으로 추론한 스키마와 스펙 선언 스키마의 필드 일치율
(필드명 · 타입 · 배열성 · 필수 여부). 게이트웨이 계열의 루트 래퍼 어긋남과
`item` 배열성 미표기가 여기서 판정된다.

### K1~K3 실행 조건 (구속력)

1. 인증키는 환경변수로만 주입한다. 명령행 인자 · 파일 · 결과물 어디에도 남기지 않는다.
2. **`CALL_BUDGET` 하드 가드를 반드시 설정한다.** 무가드 실행 금지.
   일일 개발계정 한도가 10,000회인 데이터셋이 있으므로, 백필·재시도가 라이브 한도를
   잠식하지 않도록 예산을 항목별로 나눠 배정한다.
3. 응답 실데이터는 **카세트로만** 남기며 저장 시점 스크러빙을 거친다.
   개인정보가 섞일 수 있는 응답(사업자 정보 등)은 값 기반 스크럽 대상을 별도로 정의한 뒤에만 녹화한다.
4. 실행 로그 · 결과 파일에 실응답 본문을 싣지 않는다. 싣는 것은 **집계 수치**뿐이다.

## 7. 선등록 고정 조항 + 개정 이력

### 7-1. 고정 조항

1. **프로토콜에 없는 항목을 측정하지 않는다.** 새 항목이 필요하면 문서를 먼저 고친다.
2. **측정 결과를 본 뒤 프로토콜을 고치지 않는다.** 그럼에도 고쳐야 하는 사유가
   생기면 §7-2 표에 **무엇을 · 왜 · 언제**를 남긴다. 사후 수정 자체를 숨기지 않는 것이
   선등록의 요점이다.
3. **이상치 제거 · 조건 사후 추가 · 유리한 실행 회차 선택을 하지 않는다.**
   같은 라벨로 여러 번 돌렸다면 그 사실과 파일들을 함께 남긴다.
4. **결과 수치는 이 문서에 적지 않는다.** 이 문서에 수치가 나타나는 순간
   선등록 물증으로서의 가치가 사라진다.
5. `--quick` 실행 결과는 **인용하지 않는다.** 파일 스스로 `mode: "quick"`으로 밝힌다.

### 7-2. 개정 이력

## 8. 한계와 반박 대비 — 측정하지 않은 것을 먼저 적는다

### 8-1. 이 수치가 **아닌** 것

- **경쟁 라이브러리와의 비교가 아니다.** 다른 MCP 브리지·OpenAPI 변환기와 같은
  조건에서 재지 않았다. B4의 `bare` 대조군은 "MCPortal이 없을 때"이지
  "다른 제품을 썼을 때"가 아니다.
- **실서비스 종단 지연이 아니다.** 네트워크 왕복 · 게이트웨이 처리 시간 · LLM 추론
  시간이 전부 빠져 있다. 실사용에서는 이 계층 비용이 네트워크 지연에 묻힐 가능성이 크지만,
  **그 가능성을 근거로 계층 비용을 안 재는 것**은 정직하지 않다고 보아 재서 공개한다.
- **큐레이션 효용의 증거가 아니다.** 무키 5종은 전부 성능 계량이며, 2층 구조의
  효용은 K2(§6)에서만 판정된다.
- **처리량(throughput) 측정이 아니다.** 전 항목이 단일 스레드 순차 실행이다.
  동시성 하의 쿼터가드 락 경합은 재지 않았다.

### 8-2. 알려진 한계

| # | 한계 | 영향 |
|---|---|---|
| L1 | 카세트 매칭은 선형 탐색이다. B1은 상호작용 10건 기준값이며, 카세트가 커지면 왕복 시간이 늘어난다 | B1 절대값을 카세트 크기와 무관한 상수로 읽으면 안 된다 |
| L2 | B4는 원장 SQLite 쓰기를 **포함**한다. 배치 쓰기·비동기 flush를 도입하면 값이 크게 달라질 수 있다 | 이 값은 "현재 구현의 비용"이지 "가드라는 개념의 하한"이 아니다 |
| L3 | 항목 실행 순서가 고정(B1→B5)이고 프로세스를 재기동하지 않는다. 앞 항목이 남긴 힙 상태·인터프리터 캐시가 뒤 항목에 영향을 줄 수 있다 | 항목 간 절대값 비교보다 **항목 안의 조건 간 비교**를 신뢰한다 |
| L4 | 단일 머신 · 단일 실행이다. 반복 실행 간 분산(run-to-run variance)은 측정하지 않았다 | 다른 환경의 수치와 직접 비교하지 않는다. 환경 블록을 함께 읽는다 |
| L5 | B5는 fastmcp 버전에 강하게 의존한다. 상위 라이브러리 판올림으로 값이 바뀔 수 있다 | `packages.fastmcp` 버전과 함께 읽는다 |
| L6 | 입력이 합성이다. 실제 정부 스펙 문서는 더 크고 지저분하다. 프리셋 번들이 존재하는 실행에서만 실스펙 조건이 함께 측정된다 | 합성 조건만 있는 결과 파일은 **하한값**으로 읽는다 |
| L7 | 무키 5종에는 **정확도 축이 없다.** 빠르다는 것이 옳다는 뜻은 아니다 | 정확도는 K1·K3의 몫이다 |
| L8 | **`15081808` 은 K2의 "자동생성 단독" 대조군을 만들 수 없다.** 이 소스의 `info.description` 원문에 포털이 적어 둔 `serviceKey=[서비스키]` 사용 안내가 들어 있어, 큐레이션을 끄면(`compile_preset(curated=False)`) 시크릿 게이트가 `build_openapi` 단계에서 컴파일을 막는다. 큐레이션의 `service.description` 교체가 그 문자열을 끊는 유일한 경로다 | 이 프리셋의 K2 는 S1·S2·S3 **전부 미측정**으로 보고한다. 게이트를 완화해 대조군을 만드는 선택은 하지 않는다 — 자격증명이 실린 문서를 만들지 않는다는 규약이 벤치마크 편의보다 우선한다. 나머지 3종(`15000115` · `15101612` · `15102108`)은 대조군이 정상 생성된다 |

### 8-3. 예상되는 반박과 답

| 반박 | 답 |
|---|---|
| "합성 입력으로 잰 수치는 의미 없다" | 동의한다. 그래서 프리셋 번들이 있으면 실스펙 조건을 함께 재고, 없으면 결과가 하한값임을 §8-2 L6으로 밝힌다 |
| "N이 작다" | 항목별 N과 warmup을 §4-1에 실행 전 고정했고, 원자료 배열을 결과 파일에 전부 실어 재검산이 가능하게 했다 |
| "유리한 실행만 골라 실었을 것" | 결과 파일에 프로토콜 지문 · 라벨 · 모드가 박혀 있고, `--quick` 결과는 파일 스스로 준수 실행이 아님을 밝힌다. 실행 회차를 골랐다면 §7-1(3)의 위반이다 |
| "오버헤드가 크다" | 크면 큰 대로 싣는다(§7-1(2)). 개선은 다음 마일스톤의 일이고, 수치를 고치는 것은 이 프로토콜이 금지한다 |

## 9. 결과 파일 스키마

경로: `benchmarks/results/bench_<YYYYMMDD>_<label>.json`
저장 규약: **UTF-8(BOM 없음) · LF · 끝 개행 1개 · `sort_keys=True` · `ensure_ascii=False` · 들여쓰기 2칸.**

```json
{
  "schema": "mcportal.benchmark/1",
  "protocol": "benchmarks/PROTOCOL.md@<sha256 앞 12자>",
  "mode": "full",
  "label": "dev",
  "measured_on": "YYYY-MM-DD",
  "overrides": {},
  "environment": {
    "python_version": "…", "implementation": "…", "system": "…",
    "release": "…", "machine": "…", "processor": "…",
    "cpu_count": 0, "sqlite_version": "…",
    "packages": {"httpx": "…", "mcportal": "…", "fastmcp": "…"}
  },
  "items": [
    {
      "id": "B4",
      "title": "쿼터가드 오버헤드",
      "status": "ok",
      "conditions": [
        {
          "name": "guarded", "status": "ok", "n": 0,
          "min_ns": 0, "median_ns": 0, "p95_ns": 0,
          "mean_ns": 0.0, "stdev_ns": 0.0,
          "samples_ns": [], "samples_truncated": false
        },
        {"name": "presets", "status": "skipped", "reason": "…"}
      ],
      "derived": {},
      "notes": ["…"]
    }
  ]
}
```

| 필드 | 규칙 |
|---|---|
| `schema` | `"mcportal.benchmark/1"` 고정 |
| `protocol` | `"benchmarks/PROTOCOL.md@"` + 이 문서 바이트의 sha256 앞 12자 |
| `mode` | `"full"` 또는 `"quick"` |
| `overrides` | `--repeat` · `--only`를 쓴 경우에만 채워진다. 기본 `{}` |
| `items[].status` | `"ok"` · `"skipped"` · `"failed"`. 뒤 둘은 `reason` 필수 |
| `conditions[].status` | `"ok"`(통계 필드 전부) 또는 `"skipped"`(`reason`만) |
| `samples_truncated` | §4(3)의 표본 상한을 넘어 균등 추출했을 때 `true` |
| `derived` | 항목별 파생값. B3는 `deterministic`·`first_mismatch_offset`·`determinism_runs`, B4는 오버헤드 4종 |

### 9-1. 저장 직전 게이트

1. 결과 dict 전문을 직렬화해 `mcportal.replay.scrub.find_key_assignments`로 검사한다.
   **하나라도 적중하면 저장을 중단하고 파일을 만들지 않는다**(오류 종료).
2. 한 항목이 실패해도 나머지 항목은 계속 측정한다. 하나라도 `failed`면 종료 코드 1.
3. 저장 실패 · 게이트 적중 시에도 부분 파일을 남기지 않는다.
